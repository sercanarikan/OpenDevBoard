# Architecture decision records

Use an ADR for a significant, durable architectural decision with meaningful alternatives or consequences, such as changing a system boundary, persistence guarantee, or major dependency. Routine fixes, local refactoring, and typo corrections do not require an ADR.

Copy [the template](template.md) to a numbered, descriptive Markdown file. The author proposes the decision and affected maintainers review it with the change. Record context, options, consequences and status; link related PRs without secrets or customer data. When a decision is superseded, retain the record, update its status, and link the replacement.
